# Этап 1: ядро обучения — схема и API (согласовано 14.11.2026)

Подробности к этапу 1 из `docs/PLAN-SUPERAPP.md`. Код пишется после согласования. Игра после этапа выглядит и играется так
же, но вопросы ей выдаёт ядро, и оно помнит, что человек знает.

## Что сейчас

- **Контент** копируется из `D:\Utreys-Survivors\data\learning-*.js` скриптом `tools/build-course.mjs` в `live/course.js`
  (`window.COURSE`). Там же правила игры: `rules` (3 вопроса, 2 для сдачи, награды, аудит), `maze`, `rooms` и `grading`.
- **Логика тестов** в `live/edu.js`: выбор вопросов терминала (`terminalQuestions`, из сида смены), сессия теста
  (`begin` / `select` / `submit` / `advance`), табель (`summary`). Типы: `single`, `multiple`; `open` пропускаются.
- **Вопросы терминала зависят только от сида смены.** На этом держатся повтор смены, продолжение сохранённой смены и
  проверка `edu-check` (наборы терминалов не пересекаются).
- **Результаты** живут только внутри смены (`S.ed.answers`). После смены в сохранение попадает итог по курсу
  (`byCourse`: смены, победы, лучшая оценка); какие вопросы человек знает, не хранится.
- **Облачное сохранение**: правила Firestore пропускают только `v == 4` и фиксированный список ключей.

## Решения владельца (14.11)

Принято: 1 — да, 2 — открытые вопросы не нужны (тип `open` убран, 9 вопросов не перенесены), 3 — да («слабые» — это
вопросы, на которых ошибся сам человек; пока ошибок нет, порядок как раньше), 4 — да.

Исходные формулировки:


1. **Где хранится контент.** Предлагаю перенести его сюда: `content/courses/<id>.json` становится источником, а
   синхронизация с `D:\Utreys-Survivors` прекращается (один последний импорт). Иначе новые типы и курс «Мониторинг» придётся
   вести в другом проекте. *Если оригинал должен остаться источником для двух существующих курсов — скажи, сделаю импорт
   этих двух курсов, а новые курсы будут жить здесь.*
2. **Открытые вопросы (9 штук)** — карточки самопроверки. На этапе 1 они только хранятся и учитываются в освоении по
   самооценке; показываться начнут в уроках (этап 2).
3. **Терминалы задают сначала слабые вопросы.** Наборы по-прежнему не пересекаются и определяются в начале смены, но
   учитывают освоение. Две смены с одним сидом у разных людей дадут разные вопросы.
4. **Курс-заглушка «Мониторинг»** виден в разработке, а в публичной сборке скрыт (флаг `stub`).

## Схема вопроса v2

Общие поля: `id` (уникален в курсе и не меняется — к нему привязано освоение), `topic`, `type`, `text`, `explanation`,
необязательные `image` (`{ src, alt }`), `reference`, `level` (1–3), `tags`, `stub`, `sinceVersion` (с какой версии курса вопрос задаётся).

| `type` | Свои поля | Ответ человека | Верно, если |
|---|---|---|---|
| `single` | `options: [{ id, text, image? }]`, `correct: [id]` | `[id]` | совпал |
| `multiple` | то же, `correct: [id, …]` | `[id, …]` | множество совпало ровно (как сейчас) |
| `true_false` | `correct: true \| false` | `true \| false` | совпал |
| `image_choice` | как `single`, у вариантов обязательно `image` | `[id]` | совпал |
| `order` | `items: [{ id, text }]`, `correct: [id, …]` по порядку | `[id, …]` | порядок совпал |
| `pairs` | `left`, `right: [{ id, text }]`, `correct: [[l, r], …]` | `[[l, r], …]` | все пары верны |
| `gap` | `text` с `___`, `accept: ["…"]` | строка | совпала с одним из `accept` без учёта регистра, пробелов и ё/е |
| `hotspot` | `image`, `areas: [{ id, rect: [x, y, w, h] }]` в долях 0–1, `correct: [id]` | точка `[x, y]` в долях | попала в верную область |
| `case` | `steps: [вопрос, …]` (шаги — вопросы любых типов выше, кроме `case`) | ответы по шагам | все шаги верны |
| `template` | `gen` (имя генератора), `params` | как у созданного вопроса | как у созданного вопроса |

`check` возвращает не только «верно/неверно», но и долю (`score` 0–1): для `pairs`, `order` и `case` она показывает, насколько
человек был близок. В освоение идёт только «верно/неверно», доля — для статистики и разбора.

Существующие вопросы переносятся без изменений: их `id`, тексты и ключи те же, `weight` у вариантов отбрасывается (не
используется). Старые результаты `byCourse` остаются действительными.

## API `window.LEARN`

```js
LEARN.course(id)                          // курс: { id, title, topics, questions, … }
LEARN.question(courseId, qid)             // вопрос
LEARN.make(q, rng)                        // экземпляр для показа: варианты перемешаны, шаблон развёрнут
LEARN.check(q, answer)                    // → { correct, score, detail }
LEARN.pick(state, { course, topic?, count, kinds, rng, today, exclude? })   // → [вопрос], без повторов
LEARN.record(state, course, qid, correct, today)  // → новое состояние (исходное не меняется)
LEARN.snapshot(state, course)             // → для смены: { qid: ранг }, 0 — ошибся в прошлый раз, 1 — новый, 2–6 — знает (1 + коробка)
LEARN.rank(snap, qid)                     // ранг вопроса в снимке (нет в снимке — 1, новый)
LEARN.mastery(state, course, today)       // → по темам: { total, asked, mastered, due, weak, done }
LEARN.courses({ stubs })                  // видимые курсы; заглушки — только в сборке для разработки
LEARN.GEN[name] = (params, rng) => вопрос // генераторы шаблонов (live/learn/templates.js)
LEARN.day(date)                           // номер дня по местному времени (для повторов)
```

`kinds` — какие типы умеет показать режим. Игра берёт `single` и `multiple` (её экран теста рисует только варианты);
уроки этапа 2 — все.

## Освоение (Лейтнер)

Состояние: `{ v: 1, q: { ['курс:qid']: [коробка, день следующего повтора, верных, всего] } }`.
- Коробки 0–5. Новый вопрос — коробка 0. Верно — коробка +1, повтор через 1, 2, 4, 8, 16 дней (по коробке). Неверно —
  коробка 1, повтор завтра.
- Тема освоена, когда 80 % её вопросов в коробке 3 и выше.
- В освоение идёт только **первая** попытка вопроса за смену или урок: повторная попытка после разбора не считается знанием.

`pick` выбирает так: сначала вопросы, которым пора на повтор (самые просроченные первыми), затем слабые (низкая коробка), затем
новые; внутри группы — случайно из переданного `rng`. Заглушки (`stub`) — только если курс-заглушка выбран явно.

## Игра на ядре

- **В начале смены** `META.runOpts` кладёт в опции смены `learn: LEARN.snapshot(D.learn, курс)`. Снимок сохраняется вместе с
  приостановленной сменой. Повтор и продолжение смены дают те же вопросы.
- **Терминалы.** `terminalQuestions` упорядочивает вопросы темы по снимку (слабые первыми, внутри коробки — из сида) и режет
  на непересекающиеся наборы, как сейчас. Без снимка (демо, проверки) — порядок как сейчас, из сида.
- **Тест возрождения** — так же, из снимка по всем темам.
- **Проверка ответа** в `edu.js` (`submit`) вызывает `LEARN.check`. Сессия теста, награды, аудит, табель и оценка за курс не
  меняются.
- **После смены** `META.bank` записывает первые попытки из `S.ed.answers` в `D.learn` через `LEARN.record`.

## Сохранение v5

- В `fresh()` (`live/meta.js`) добавляется `learn: { v: 1, q: {}, xp: 0, streak: { days: 0, last: 0, freeze: 0 } }`;
  `xp` и `streak` начинают использоваться на этапе 2. Миграция v4 → v5: раздел создаётся пустым, остальное как есть.
  Резервная копия v4 остаётся в `localStorage`, как при прошлых миграциях.
- Размер: около 30 байт на вопрос, 1000 вопросов — 30 КБ.
- **Правила Firestore** (`progress/{uid}`): принимать `v == 4` и `v == 5`, ключ `learn` — словарь не больше 2000 вопросов.
  **Порядок выкладки:** сначала владелец выкладывает правила (`firebase deploy --only firestore:rules`), потом выходит
  клиент. Иначе облачное сохранение новой версии будет отклонено. `rules-check.mjs` дополняется.

## Курс-заглушка «Мониторинг»

`content/courses/monitoring-stub.json`, все вопросы `stub: true`, тексты вымышленные:
- 2 × `true_false`, 2 × `order` (шаги разбора инцидента), 2 × `pairs` (симптом ↔ дашборд), 2 × `gap`;
- 2 × `hotspot` по нарисованной схеме дашборда (SVG в `live/learn/img/stub/`, не скриншот);
- 1 × `case` на 3 шага;
- 2 × `template` `chart`: генератор отдаёт ряд данных и варианты ответа («всплеск», «утечка», «падение в ноль», «норма»);
  рисовать график начнём на этапе 2.

Курс не входит в Учебный центр (его нет в `content/index.json`): он для проверки ядра и для экранов этапа 2.

## Порядок работы (коммиты)

1. **Контент.** `content/*.json`, `build-content.mjs` со всеми проверками схемы собирает `live/course.js`; `edu.js` читает
   вопросы оттуда. Поведение игры не меняется, `edu-check` проходит как есть.
2. **Ядро.** `learn/core.js`: `check` для всех типов, `pick`, `record`, `snapshot`, `mastery`; `learn-check.mjs`.
3. **Сохранение v5.** Миграция, правила Firestore, `ach-check` и `rules-check` дополняются. Правила выкладывает владелец.
4. **Игра на ядре.** Снимок в опциях смены, терминалы по снимку, запись результатов после смены. `edu-check`:
   наборы по-прежнему не пересекаются, со снимком первыми идут слабые.
5. **Заглушка «Мониторинг»** и генератор `chart` (данные).

После каждого шага: все проверки без браузера и ручной заход в Учебный центр.
