# Firebase для NetSurvivors: что сделать вам

27.10.2026. По образцу `docs/FIREBASE-SETUP.md` оригинала, но для **отдельного** проекта (ваше решение): правила, квоты и данные
основной игры не затрагиваются. Всё бесплатно на тарифе Spark, карта не нужна. Код входа, отправки забегов и таблиц, правила
Firestore и тесты на эмуляторе я пишу сам; от вас нужны только шаги в консоли, к которой есть доступ лишь у вас.

## 1. Создать проект (≈5 минут)

1. Откройте https://console.firebase.google.com → **Создать проект** (Add project).
2. Имя: например `netsurvivors`. Запомните **Project ID** под именем (например `netsurvivors-1a2b3`) — он нужен на шагах 5 и 6.
3. Google Analytics — отключить. Тариф — оставить **Spark**.

## 2. Зарегистрировать веб-приложение

1. В обзоре проекта — значок **</>** (Web).
2. Имя: `NetSurvivors`. Галочку **Firebase Hosting** пока не ставьте (публикация — отдельный шаг, см. ниже).
3. Скопируйте объект `firebaseConfig` (`apiKey`, `authDomain`, `projectId`, `storageBucket`, `messagingSenderId`, `appId`).
   Это **не секрет**: эти значения всё равно видны в коде страницы, базу защищают правила Firestore.

## 3. Включить вход по логину и паролю

Игрок вводит только логин и пароль; игра сама превращает логин в служебный адрес, email не нужен.

**Build → Authentication → Get started → Sign-in method**:
1. **Email/Password** → включить первый переключатель; второй (**Email link / passwordless**) — выключен → **Save**.
2. Другие провайдеры не включать.
3. **Settings → Authorized domains**: `localhost` там уже есть — игру для входа открывайте по `http://localhost:8931/live/index.html`
   (не `127.0.0.1`). Если хотите и `127.0.0.1`: **Add domain** → `127.0.0.1`.
4. **Settings → User actions**: «Enable create (sign-up)» оставить включённым.

## 4. Создать базу Firestore

**Build → Firestore Database → Create database**:
1. Режим **Standard**.
2. Регион `eur3 (europe-west)` или ближайший. **Регион потом не меняется.**
3. Правила — **Production mode** (всё закрыто). Настоящие правила выкатятся на шаге 6.

## 5. Прислать мне конфигурацию

Пришлите `firebaseConfig` из шага 2 в чат (или Project ID и скриншот блока). Я запишу его в `live/firebase-config.js` и
`.firebaserc`. Пока файла нет, игра работает как сейчас, без входа и таблиц.

## 6. Выкатить правила (после того как я их напишу и проверю на эмуляторе)

Firebase CLI у вас уже есть в оригинале. Если вы входили в него под тем же Google-аккаунтом, повторять `firebase login` не нужно.
Из папки `D:\Utreys-NetSurvivors` в PowerShell:

```powershell
D:\Utreys-Survivors\node_modules\.bin\firebase.cmd deploy --only firestore:rules --project <Project ID>
```

Без правил база закрыта и регистрация не работает. Каждое изменение правил (например, новая карта в таблицах) выкатывается этой
же командой.

27.10 правила дополнены документом `progress/{uid}` — достижения игрока. Пока новые правила не выкачены, игра работает как
раньше, только достижения не попадают в профиль. Выкатить нужно той же командой с `--project netsurvivors`. Выкачено 27.10 (14:17 UTC): правила в проекте совпадают с `firestore.rules`. Если в игре
появляются новые достижения, их id нужно добавить в `knownAch()` в `firestore.rules`: `tools/rules-check.mjs` сверяет список
с `live/ach.js`. После этого правила выкатываются снова.

27.10 (позже) в `progress/{uid}` добавлено поле `epoch` — сброс прогресса из «Настроек». Правила нужно выкатить ещё раз той же
командой.

Затем список достижений вырос до 79 (лимит длины списка — 128): правила нужно выкатить ещё раз.

## 7. Проверить

1. Откройте игру по `http://localhost:8931/live/index.html` — в главном меню появится кнопка «Войти».
2. Зарегистрируйтесь логином, например `Тест1`. В **Authentication → Users** появится пользователь с адресом из цифр и букв a–f
   `…@<projectId>.firebaseapp.com` — это закодированный логин, так и должно быть. В **Firestore → Data → logins** — документ `тест1`.
3. Сыграйте смену дольше 10 с: в **Firestore → Data → stats** у вашего uid вырастут `games`, `totalKills`, `totalCodes`; забег
   появится на экране «Лидеры».

## Публикация (по желанию, позже)

Вход работает только с разрешённого домена. Проще всего публиковать срез на **Firebase Hosting** этого же проекта: домены
`<projectId>.web.app` и `<projectId>.firebaseapp.com` разрешены сразу. Скажите, когда захотите, — я подготовлю `firebase.json`
для хостинга, а команду публикации запустите вы.

## Защита и квоты (как в оригинале)

- **Ограничить API-ключ:** Google Cloud Console → APIs & Services → Credentials → ключ *Browser key (auto created by Firebase)* →
  **API restrictions → Restrict key**: Identity Toolkit API, Token Service API, Cloud Firestore API.
- **Квоты:** оставайтесь на Spark — при исчерпании дневной квоты Firestore просто перестаёт отвечать до полуночи (PT), денег не
  списывают; игра работает, забеги догонят из очереди. Лимиты: 50 тыс. чтений, 20 тыс. записей в день. Нагрузка — **Firestore → Usage**.
- **Сброс пароля и бан** — как в оригинале, через ключ сервисного аккаунта (**Project settings → Service accounts → Generate new
  private key**, хранить вне репозитория и никому не пересылать). Скрипты подготовлю, когда понадобятся.

## Что решено (по образцу оригинала)

- Логин: кириллица или латиница (не вперемешку), цифры, `_`, `-`, 3–16 символов, без учёта регистра, «ё» = «е». Логин и есть имя в таблицах.
- Таблицы (общие и по карте): лучшее время смены, сбоев за смену, кодов за смену, быстрая победа (раньше закрыт инцидент — выше),
  лучший уровень; в «Моей статистике» ещё всего смен, сбоев и кодов. Учебный центр в таблицы не идёт (как в оригинале).
- Смотреть таблицы можно без входа; забег отправляется, если игрок вошёл и смена длиннее 10 с; без сети — очередь в браузере.
